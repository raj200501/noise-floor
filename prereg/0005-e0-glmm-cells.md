# 0005 E0 part 2 (amends 0003): coverage cells behind the E1 headline intervals

- Date: 2026-11-11
- Amends: `prereg/0003-e0-coverage-grid-part1.md`, which announced this part 2 ("the logit GLMM
  variance-component cells, shaped like the E1 design ... frozen before E0 part 2 and before any
  E1 confirmatory data"). This file adds cells and changes nothing in 0003, whose rule still
  holds. This amendment will be reported in docs/REPORT.md as a deviation from 0003: the GLMM
  cells are the part 2 that 0003 announced; the local-arm, Claude-slice, sampling, and bound
  cells and the E1 headline map go beyond it, because every E1 headline interval needs a cell
  (gate G5).
- Frozen in the same commit as `prereg/0004-e1-factorial.md` (E1) and `prereg/0006-g6-recovery.md`
  (G6), before any E0 part 2 replicate and before any E1 confirmatory run.
- All data here is synthetic.

## Cells

The ```json e0-grid``` block lists 175 cells, each with a nominal level of 0.95, 500
replicates for the GLMM cells and 2,000 for the others (G5). The ```json headline``` block maps
every E1 headline interval of prereg 0004 to its cells, and the ```json headline-kinds``` block
gives each headline cell's kind. The cells and planted values were generated by
`tools/prereg_blocks.py` (D-032, D-033). Each cell's method and interval type name the library
function and interval label whose validity check the cell feeds (D-033 item 7).

- GLMM cells, in two groups that each share their datasets: replicate `i` of group `g` is one
  dataset simulated with seed `noisefloor.recovery.e0_glmm_seed(g, i)` from the ```json
  recovery-config``` block, with the group's planted overrides, and analyzed once by exactly the
  E1 analysis of prereg 0004. The datasets have the shape of the E1 local arm: 3 models x
  85 tasks x the 16 runs of the half fraction, with each cell's 2 replicate runs dealt into the
  batches of one model and one concurrency level over 4 days x 2 blocks by the function that
  `noisefloor.e1.local_plan` uses and then left out, as the E1 decomposition leaves them out.
  Each cell's replicate line holds its component's planted value (`truth`), the estimate, and the
  interval; a missing interval counts as not covered. Random-variance cells are method
  `glmm_component` with interval type `parametric_bootstrap`, fixed-contribution cells
  `glmm_task_jackknife`, share cells `glmm_plugin_share`, and MDE cells method `glmm_mde` with
  `parametric_bootstrap`.
  - Group `e1` (the planted values below): one cell per decomposition component (task,
    model:task, model, harness, timeout, steps, temperature, concurrency, day, block), one per
    share of the total (those ten and the residual), and one per row of the MDE table (15
    designs). A planted share is the component's planted value over the sum of the planted
    values of the analyzed components plus pi^2/3. For a given number of runs k, the five MDE
    cells at different task counts scale together (the estimate, every replicate, and the
    planted MDE are all proportional to 1 / sqrt(T)), so they amount to one test per k.
  - Group `e1-het` (D-028 item 5): the same planted values plus task-by-harness, task-by-steps,
    and task-by-timeout variances of 0.25 each (each task's own effect at each level of those
    factors, outside the analysis model), with one cell per fixed-factor contribution and one
    per its share. A fixed contribution's planted value stays the variance of its main-effect
    contribution; the task truth behind the shares is the planted task variance plus half of
    each task-by-factor variance, which the analysis model's task term targets.
- Local-arm cells (2,000 replicates, no GLMM fit; `noisefloor.recovery.local_intervals`, the
  computation of prereg 0004 items 3 to 5), on datasets of the same shape: each local model's
  success rate (`cluster_t` over its 85 tasks), its harness contrast (level 1 minus level 0 of
  the simulated harness, paired by task, `cluster_t`), the difference of every two models'
  harness contrasts (method `contrast_difference`, `cluster_t`), and every pair of models on the
  level 0 (minimal-agent) runs (`cluster_t`), in six groups with their own datasets: `e1-local`
  at the planted values; `e1-local-lo2`, `e1-local-lo`, and `e1-local-hi` with the intercept at
  -3.0, -1.5, and 1.5, so that low and high local scores lie inside the validated range;
  `e1-local-mh`, with model-by-harness effects of -0.5, 0, and 0.5 on the logit scale, so that
  harness differences of the size E1 can detect are covered; and `e1-local-eq`, with model
  effects 0.3, 0.3, and -0.3, so that a pair of equal models is covered. Models are identified by
  their position in the planted model effects. A planted value is the mean, over the runs the
  interval uses, of each run's success probability with its task and model:task effects
  integrated out (the super-population quantity a task-clustered interval estimates).
- Claude-slice cells (2,000 replicates; the part 1 simulators, task variance 2.0 and
  model-by-task variance 0.5 on the logit scale as in part 1, 30 tasks; the Claude tiers were
  not piloted, so no estimate of their variances exists):
  - tier success rates (`cluster_wilson`, 2 runs per task) at intercepts -2.0, 0, 2.5, 3.5,
    4.5, and 5.5;
  - tier pairs under one harness (`mover_wilson`, 1 run per side, two tiers with their own
    model-by-task effects and the same timeout, as in the Claude plan) with effect 0.4 at
    intercepts -2.0, 0, 2.5, 3.5, and 4.5, no effect at intercept 3.5, and effects 1.0 and 2.0 at
    intercepts 0 and 2.5;
  - within-tier harness contrasts (`mover_wilson`, 1 run per side; both sides share the task and
    model-by-task effects, and each task's pair also differs in timeout by 0.4 on the logit
    scale, the shifted side alternating by task as in the Claude plan; review stats-4) at the
    same intercepts and effects;
  - Claude-local comparisons (`mover_wilson`, 1 run against 4) with the local side at intercept
    0 and the tier 0, 0.4, 2.5, 3.5, or 4.5 higher, at intercept -1.5 with the tier 3.5 or 6.0
    higher, and at intercept -3.0 with the tier 4.5 or 6.0 higher. The Claude side of a real
    comparison alternates between the two timeouts by task, which these cells do not simulate.
- Sampling-table cells (method `sampling_discordance`, `cluster_wilson`, 85 tasks): the data of
  the sampling table itself (prereg 0004 item 6, D-031 item 1). Three models with the planted
  model effects 0.6, 0, and -0.6, task variance 4.0, and model-by-task variance 0.5 each run two
  independent runs per task at one configuration; a pair is discordant when its outcomes differ.
  The interval is half the task-clustered Wilson interval of the discordant share, and the truth
  is the mean over the models of E[p (1 - p)]. Cells at reference intercepts 0, 2.0, 4.0, and
  6.0, and at intercept 0 with task variance 1.0 (more runs near one half).
- E3 bound cells (Imbens and Manski, 16 runs per task, task variance 4.0, no model-by-task term,
  85 tasks): a share of the runs is marked ambiguous and recorded as 0. In the headline cells
  each true failure (or each true success) is ambiguous with a given probability: 0.05 or 0.4
  among failures or among successes at intercept 0, and 0.8 among failures at intercepts -1.5
  and 1.5. Among failures the truth lies at the set's lower end; E1 lies at or above it (at it
  when no ambiguous run has outcome 1, since timeouts keep their graded outcome; review
  stats-14). Among successes the truth lies at the upper end (review stats-10). The quantity E1
  compares with these cells is each model's ambiguous share of all runs.
- Reported extras, not headline: `cluster_t` score cells at 2 runs per task and intercepts 2.5,
  3.5, and 4.5 at 30 tasks, beside the `cluster_wilson` cells (review writing-25), and bound cells
  with each run ambiguous with probability 0.05 or 0.4, among all runs.

Planted values (D-032, D-033): the factor effects (harness 0.5, timeout 0.4, steps 0.4,
temperature 0.1, concurrency 0 on the logit scale), the day effects (0, 0.1, -0.1, and 0.05 for
the fourth day), the block effects (0, 0.05), and the model:task variance 0.5 are design values,
assumed and not estimated from any data; the method pilots used the same values for the first
three days. The task variance is 4.0 because screening s3 showed many tasks with the same
outcome in every run, which variance 2.0 makes unlikely (D-028 item 5). The three model effects
are spread evenly from 0.6 to -0.6. No batch variance is planted in these cells; prereg 0004
handles batch variance through the batch-term sensitivity rule and the post-E1 check. The
simulated design has exactly 4 days and 2 blocks with every batch on its planned slot; prereg
0004 says how day and block are reported if the arm runs otherwise.

## Rule

Unchanged from 0003 (gate G5): a cell passes if its coverage is at least
`nominal - 0.015 - 2 * MCSE`, with MCSE `sqrt(c (1 - c) / R)`; over-coverage is reported, not
failed. A failing cell is listed as unsupported in `evalstats.validity`, and the function its
method names warns (`UnsupportedDesignWarning`) when it is used with the cell's interval type on
a design with at most the cell's number of tasks; G5 checks that warning for every failing cell.
The headline status of each kind of E1 interval follows D-023, D-028, and D-033 on the
exploratory pilots (every kind met the rule: random variances, fixed contributions with the task
jackknife, shares, and MDE rows), so every cell named in the headline block is a headline cell
and G5 requires it to pass. Mapping rule, as in prereg 0004: an E1 interval of a kind is backed
by all cells of that kind; if any fails, every interval of that kind is reported as resting on
an unsupported method and G5 fails, unless dated amendments frozen before the first confirmatory
E1 run replace that kind's method: one of prereg 0003 that adds headline cells of the kind for
the new method, which G5 then requires to pass; one of prereg 0004 that allows the new analysis
code; and, for a GLMM kind, one of prereg 0006 that reruns G6 with the new method on new seeds.
The amendment of 0003 lists the replaced cells in a ```json retired-headline``` block: they
then back no headline interval, stay in the grid, and if they fail are listed as unsupported with
a warning. G5 accepts the retirement only beside new headline cells of the kind that test another
method (another method or interval type; for a GLMM kind, another rule in the amendment's own
block ```json recovery-config```, where the box rule does not count for fixed contributions under
the task jackknife) and a frozen amendment of 0004 from before the first confirmatory E1 run
whose ```json analysis-code``` block allows the new analysis code (an amendment of 0004 for
another purpose does not count). The spans in the ```json validated-range``` block are the planted values
each headline kind's cells cover, on the scale E1 compares: success rates;
differences in absolute value (each paired interval mirrors when its two sides swap; a kind's
span starts at 0 when one of its cells plants no difference, `null_cells`); the
sampling table's within-configuration variance; and each model's ambiguous share for the bounds.
The E1 analysis compares each interval's point estimate with its kind's span. The GLMM kinds
have no span rule, as the post-E1 check of prereg 0004 tests them at the E1 estimates.

## Running and banking

- Grouped cells (GLMM and local-arm): `python -m noisefloor.recovery e0-run
  prereg/0005-e0-glmm-cells.md --workers N`. Other cells: `python -m noisefloor.e0_run run
  prereg/0005-e0-glmm-cells.md`, which skips the grouped cells. Both resume where they stopped;
  a dataset whose lines were cut between components runs again, and its later line counts.
- Bank: `python -m noisefloor.e0_run bank prereg/0003-e0-coverage-grid-part1.md
  prereg/0005-e0-glmm-cells.md --only prereg/0005-e0-glmm-cells.md` writes only
  `artifacts/e0/coverage-0005.json`, which cites this file (D-026), and leaves the part 1
  artifact as it was banked; `python -m noisefloor.e0_validity` then regenerates
  `artifacts/headline_cells.json` and the library's list of failing cells
  (`src/evalstats/data/validity.json`). Order (D-034): G6 and E0 part 2 both write all their
  rows first; then both are banked, `e0_validity` runs, and its outputs are committed before the
  local arm's first batch and before the Claude slice's clone. That commit is the one change
  under `src/` from the start of G6 to the E1 analysis; the list is outside the analysis-code
  pin, which it would otherwise change.
- Every raw line carries a provenance stamp (environment hash, analysis-code hash, commit, a
  dirty flag for `src/`, time; `noisefloor.provenance`, D-031 item 6, D-033 item 10). No commit
  changes `src/` or `uv.lock` while E0 part 2 runs: each run command refuses to add lines beside
  lines from another environment, and banking refuses the lines of this grid unless they share
  one environment and one analysis code from a clean `src/`. If lines from two environments
  exist anyway, the study's lines are set aside unread and the study runs again in one
  environment, reported as a deviation. The artifact names the environment and the analysis
  code; prereg 0004's analysis runs only under that analysis code.
- No replicate is rerun or dropped otherwise; a failed fit is a replicate without an interval.
